## Lokale MacBook-Verifikation

Repository-Pins verwenden: Rust 1.98.0, Go 1.26.6, cargo-deny 0.20.2;
native Workflows verwenden Python 3.13. Eigene Buildausgabe für diesen
Worktree verwenden. Der Cloud-Buildcache ist nicht Teil der Übergabe.

```sh
rustup toolchain install 1.98.0 --profile minimal --component rustfmt --component clippy
export CARGO_TARGET_DIR="$PWD/target/macbook-handoff"
export CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0
export CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0
cargo fmt --all --check
cargo test -p symvault-cli -p symvault-platform --all-targets --locked
cargo clippy -p symvault-cli -p symvault-platform --all-targets --all-features --locked -- -D warnings
cargo build -p symvault-cli --bin symvault --locked
```

Das lokale Testresultat wird sich wegen nativer cfgs von Linux unterscheiden;
kein Linux-Testcount soll als MacBook-Nachweis abgeschrieben werden. Unbekannte
Ignored-Tests nicht blind einschalten: die Provider-Tests verändern reale
native Zustände und verlangen ausdrücklich einen disposable Runner.

Die Validation-Abhängigkeiten sind getrennt vom Produkt:

```sh
python3 -m venv /tmp/symaira-tui-validation-20261004
/tmp/symaira-tui-validation-20261004/bin/python -m pip install -r scripts/rust-port/tui-validation-requirements.txt
```

Der volle Driver `scripts/rust-port/tui_contract.py` braucht auf Linux
`Xvfb`/`xclip` und erzeugt seinen eigenen authentifizierten X-Server. Auf
macOS/Windows verlangt er einen echten frischen GitHub-Runner mit
`SYMVAULT_DISPOSABLE_NATIVE_RUNNER=1`; er ersetzt dort die allgemeine
Zwischenablage. Ein persönliches MacBook ist kein disposable Runner. Diese
Schranke nicht durch vorgetäuschtes `GITHUB_ACTIONS` umgehen. Windows benutzt
gepinntes pywinpty mit explizitem nativen ConPTY, kein Cross-Compile-Ersatz.

Die vollständige native Workflow-Datei ist noch hinzuzufügen. Ihre Linux-,
Darwin/arm64- und Windows-Gates müssen alle 15 tatsächlichen Fälle, geheime
Canaries, Input-/Output-Modusrestoration, clean-at-start/end und vollständige
Quellen-/Binary-Bindungen prüfen. Die bestehenden `pull_request.branches: main`
Workflows laufen für den gestapelten Draft gegen #1310 nicht automatisch;
eine endgültige Abnahme ist erst nach geeignetem Workflow und aktuellem
Mergecandidate gegen `main` möglich.
