# ADR 0027: Bound the whole HTTP write phase and separate TLS admission

Status: accepted design; native acceptance pending, 2026-10-04.

## Decisions and rationale

Start one absolute write deadline after valid request headers are admitted,
before reading the entity. Each underlying TCP write uses the remaining budget,
including writes issued by rustls. Successful partial writes do not restart the
clock. Clear that deadline before waiting for the next keep-alive request, which
retains Go's separate 120-second idle allowance. This follows actual Go's write
phase: a body can finish within its read allowance but leave no time to write
the response. A per-operation socket timeout previously allowed that response.

Non-cancellable sends use nonblocking writes with bounded retry waits,
restoring blocking mode before the next read. A progressing blocking kernel
send can otherwise outlive its socket timeout on Darwin. Cancellable sockets
retain their existing shutdown-owned retry waits. TCP and rustls use this same
socket boundary.

Complete TLS admission inside the already admitted connection worker, using
one read/write deadline equal to the smallest positive effective header, read
and write budget. After the verified handshake, clear its deadlines and begin
the HTTP phases separately. Keep connection admission and cancellation
registration ahead of the handshake; a slow ClientHello must not block accept.
Existing public server entry points and configured options retain their shape.

The deadline limits socket I/O, rather than interrupting synchronous handler
computation. A callback that finishes after expiry cannot send a late response;
this change does not establish handler cancellation or CLI signal acceptance.
TLS identity lifecycle, ALPN and the remaining parser/budget cases stay open.

## Actual evidence and boundaries

Native owning suites run one test at a time so unrelated CPU-heavy fixture
construction does not contaminate wall-clock deadline assertions. Individual
tests still exercise concurrent workers; no timing bounds or case-count gates
are relaxed. The small socket test observes real bytes before expiry, explicitly
expires that phase, then proves rejected bytes are absent after the next phase
is reset. It does not assume that a fixed response size fills every operating
system's send buffers; progressing backpressure remains owned by the full
native control. A requested socket receive-buffer size alone does not prove
that the TCP receive window is bounded or that the sender remains blocked.

`http_write_contract.py` rebuilds immutable production Go
`d1cd0f97ac550bc3020bc86b0514989f8d28d95c`, generates encrypted fixtures through
its actual vault/config/token APIs and runs the actual Rust CLI. Both use the
same sequential native loopback port and byte-identical fixture clones, with
isolated HOME/XDG directories and the test memory keyring. Fresh private P-256
identities use ADR 0025's verified TLS contexts and remain outside system trust.

The original five profiles cover five-second TCP, one-second TCP/TLS 1.2/TLS 1.3 and a separate
30-second TCP output budget. Fifteen complete ordinary response pairs compare
the entire status, headers and entity, excluding only Date. In each profile,
deliver sixteen final body bytes at 150-millisecond intervals. The body completes
after at least 2.4 seconds: the five/30-second profiles return the complete ping,
whereas all three one-second profiles must produce zero HTTP application bytes
and actual peer EOF/reset. Retain TLS record-layer diagnostics and continue
observing the underlying socket after a TLS error; an exception alone does not
prove server closure. Socket ownership transfer uses Python's socket detach,
including on Windows, rather than treating a Windows socket as a CRT descriptor.
Classify Windows connection-aborted errors alongside connection resets as
terminal socket outcomes, retaining their distinct diagnostic kind. A TLS
record-layer error alone or an unrelated socket error is not closure evidence.
The synthetic socket-error regression checks this classification separately
from the real native deadline corpus.

Two actual partial ClientHellos progress one byte every 150 milliseconds and
must terminate at the one-second handshake budget, with joined sender threads,
at least nine transmitted bytes and actual EOF/reset in 0.6..2 seconds.

The output control reads a valid public metadata entry generated by actual Go.
Its bounded tags produce a chunk of 25,613,736 bytes without relaxing the store
plaintext limit. Read 1 KiB at a time with 150-millisecond pauses for 34 seconds,
then drain quickly. Require at least four real reads and 4 KiB of progress,
complete specific HTTP headers and a declared chunk above 10 MiB. Actual peer
EOF/reset must arrive while that chunk remains incomplete; client disposal
cannot count as timeout evidence. Preserve all received bytes and lengths.

The integrated Windows observation returned the complete chunk for both the
immutable Go oracle and Rust after the fast drain. That failed control is not
native acceptance, nor does late client consumption alone establish a socket
write after expiry. The original receipt has no sender-write timestamps or
effective socket-buffer observations; pre-expiry queueing remains an unproved
alternative to late writes. Keep the original byte, progress, deadline and
suite-count assertions unchanged while collecting evidence.

Receiver-only diagnostics read back `SO_RCVBUF` and `SO_SNDBUF` without changing
their requested values. Windows also reads `SIO_TCP_INFO` version 0 before
slow reads and the existing fast-drain buffer change, recording native TCP
state, cumulative inbound bytes, receive window and dynamic receive buffer
with monotonic sample start/end times. These are client socket statistics,
not server send-buffer or transport-write traces. The fixed-width 88-byte
layout follows Microsoft WinSDK `mstcpip.h`; unavailable or incomplete native
observations fail closed, including under Python optimization. Record a
diagnostic failure by phase, error class and OS code without logging payloads.
Stop telemetry after that failure or a classified peer closure, but preserve
actual received bytes and the peer outcome within the unchanged read bounds
before re-raising the diagnostic error. Telemetry failure is not EOF/reset.
Its synthetic ABI and lifecycle tests are not Windows evidence.
Native observations must distinguish already queued data from an actual
pending sender write before changing production semantics or the control.

## Additional TLS backpressure control

The loss-verified Windows observations at `be4243dc` distinguish early AFD
Location 3051 send records from Location 3073 successful-status records after fast
drain. Both Go and Rust still fail the original incomplete TCP output assertion.
These records do not establish a late application-level write; do not change
production timeout behavior merely to make this receiver-only control pass.

Add a sixth profile, `tls-output`, with verified TLS 1.3 and the same 30-second
write budget, encrypted fixture, 4 KiB requested receive buffer, 34-second slow
read phase and bounded fast drain. It must retain real progress, peer closure,
the exact server certificate fingerprint and an incomplete declared HTTP chunk.
This tests whether TLS record writes produce an actual blocked writer instead
of permitting the entire single large plaintext send to be queued early.
It is a hypothesis requiring native execution, not an assumed Windows result.

`--tls-output-probe-only` records its narrow scope explicitly and cannot satisfy
the full-corpus workflow gate. The full corpus includes all six profiles with
18 ordinary response pairs; both original short TLS handshake controls remain.
The original TCP incomplete-output assertion remains enabled on every OS while
the additional control is evaluated.

`http_write_mutation.py` temporarily disables the actual underlying socket's
write deadline and timeout before every write, builds the real Rust CLI and
runs that isolated TLS output profile against unchanged immutable Go. Success
requires the specific incomplete-output assertion to reject Rust's complete
post-drain response while Go stays incomplete, not an unrelated failure. The
runner restores and hashes the original source and executable even on failure.
Keep baseline and mutant receipts separately; native acceptance cannot be
changed until the real native positive and negative controls are established.

## Declared platform difference: Go plain-TCP output on Windows (#1470)

The native Windows observation of run 40093354990 (job 120870417174) returned
432,442 of 25,613,736 chunk bytes for Go over TLS and 245,760 for Rust over TLS,
but 25,613,743 for the immutable Go oracle over plain TCP: the oracle's expired
in-flight write completed after the fast client drain. Rust over plain TCP was
not reached because the Go assertion aborted first and remains unmeasured there.

Owner decision (2026-10-24): record exactly this cell as a declared platform
difference and keep Rust strictly checked, so Rust stays stricter than the Go
oracle. In `http_write_contract.py` only `implementation == 'go'`,
`profile == 'tcp-output'` and `native_os == 'Windows'` skip the incomplete-chunk
assertion and instead append a `declared_differences` entry carrying
`implementation`, `profile`, `native_os`, `received_chunk_bytes`,
`declared_chunk_length`, `decision` and a `reason` citing #1470. Rust on every
OS, Go on `tls-output` everywhere and Go on Linux/macOS keep the assertion with
its unchanged message, which `http_write_mutation.py` pins; the mutation control
runs Rust over `tls-output` and is therefore never masked.

The receipt validators in `rust-http-write.yml` and `rust-http-macos.yml` (and the
pinned `ci_macos_satellites_baseline.json`) require exactly that one entry on
Windows, none elsewhere, and a truncated chunk for every Rust cell. The unit
controls in `test_http_write_contract.py` are synthetic and are not native
evidence. Native Windows CI must still show Rust over plain TCP truncated.
