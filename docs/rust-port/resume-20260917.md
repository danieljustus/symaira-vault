This candidate continues PR #1069 from `fca3f894`. Go remains the production
backend; no release, cutover, or Go removal is included.

## Plan and implementation boundaries

Independent slices reuse the existing Rust workspace: production Git process
cleanup, raw configuration listing, and MCP tool catalog/list-time
filtering. Shared gates and fixture provenance are integrated together after
focused checks. Tool listing does not imply tool execution or authorization
parity; CLI family progress does not close the entire CLI contract.

## Git and native execution

The Go system-Git adapter assigns a suspended Windows child to a kill-on-close
Job Object before resuming it. Setup failures kill and reap the child, and
cancellation bounds pipe cleanup. The production adapter now has an explicit
native Windows CI step in addition to the differential harness tests.

The Git oracle advances to `28fd35315cf4989821a96bb08279c999c693e8d9`.
The regenerated fixture retains all five behavior projections unchanged;
its source/generator identities and the Rust fixture assertion advance together.

A missing-object negative control was rejected by the real gate.

Rust's Git descendant cleanup remains Unix-only. Windows currently kills the
direct child; a Rust Job Object adapter and native descendant tests remain open.
The Go Windows check cannot close this Rust gap.

## Config review boundary

The initial `config get` candidate is not integrated: parsing into
`serde_yaml_ng::Value` normalizes YAML scalar spelling and resolves aliases,
whereas Go returns node text. `config list` remains the selected CLI slice
because it can preserve the source bytes without a new YAML parser.

## MCP catalog/list slice

The native handler supports `tools/list` after initialization, all 35 Go tool
schemas, original ordering/annotations, lean listing and injected capability/
profile filters. Eleven Go-produced scenarios include custom tiers with unset,
true and false value-exposure flags. The unset versus explicit-false distinction
also preserves the Go `get_entry` schema behavior.

The fixture verifies seven production-source files against `fca3f894`, hashes
its generator, and is checked by `make mcp-list-differential` and `port-contract`.
The integrated MCP suite passes 27 tests and all-target Clippy. Runtime
capability discovery, tool execution, policy authorization and approval remain
outside this slice; MCP-002 is in progress and RUST-010 stays blocked.

## Raw config list slice

Native `config list` preserves raw file bytes, including malformed YAML, CRLF,
empty files and invalid UTF-8. Thirteen real Go CLI subprocess cases cover
quiet mode, global flags, default HOME and missing-file/path errors. The fixture
compares stdout bytes and exit status; diagnostic matching is a stable substring,
not a byte-exact stderr contract. `config get` and mutating commands remain open.

The oracle executable must carry clean `fca3f894` VCS metadata and Go 1.26.6.
Build it from an ordinary isolated clone: linked worktrees produced incorrect or
missing Go VCS metadata on this host. The generator rejects those binaries.
